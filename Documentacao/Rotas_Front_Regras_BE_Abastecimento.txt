3. REGRAS DE NEGOCIO / CONTRATOS QUE AINDA PRECISAM DO BACKEND
====================================================================

1) Regra exata de EDICAO via GravaAbastecimento
- A documentacao mostra apenas o endpoint /api/frotas/Abastecimentos/GravaAbastecimento.
- O Swagger oficial publica IdAbastecimento no endpoint de gravacao.
- O Swagger oficial NAO publica nenhum endpoint separado de update, editar, alterar ou buscar detalhes completos de Abastecimentos. So existem endpoints de Consulta* e GravaAbastecimento.
- Ainda assim, nao descreve em texto a regra de negocio que distingue CRIACAO de EDICAO.
- No frontend hoje ja enviamos variacoes de IdAbastecimento e tambem CodAbastecimentoExterno quando ele vier da consulta.
- Mesmo assim, no ambiente do cliente Francisco a API ainda responde com duplicidade no IDX_TB23_CDGWEB.

O backend precisa informar objetivamente:
- Qual campo identifica update: IdAbastecimento, AbastecimentoId, idAbastecimento, CodAbastecimentoExterno ou outro
- Se update e suportado no mesmo endpoint GravaAbastecimento
- Se existe outro endpoint ou outra versao de contrato para atualizar abastecimento existente

2) Campos faltantes na API de consulta para reconstituir a edicao completa
- Os documentos internos ja registram que ConsultaAbastecimento nao retorna todos os IDs necessarios.
- Isso afeta principalmente o fluxo proprio ao abrir detalhes/edicao.

O backend precisa esclarecer ou fornecer:
- destinoId
- empreendimentoId/emprdId
- etapaId
- blocoId
- responsavelId valido
- colaborador/frentista
- aplicacaoId
- tipoPrevAbast
- horaAbastecimento

3) Regra para destino nao equipamento no Abastecimento Proprio
- A documentacao diz para enviar IdTanqueDestino quando destinoTipo <> M.
- O frontend ja faz isso.
- Falta confirmacao do backend sobre a combinacao valida com IdEquipamento.

O backend precisa informar:
- Quando IdEquipamento deve ser omitido obrigatoriamente
- Se ha combinacoes validas para destino B, C e D

4) Contrato do codAbastecimentoExterno / TB23_CDGWEB
- A documentacao de consulta mostra codAbastecimentoExterno no retorno.
- O erro do cliente referencia o indice IDX_TB23_CDGWEB.
- O Swagger oficial de GravaAbastecimento NAO publica codAbastecimentoExterno como parametro do endpoint.
- Portanto, por contrato publicado, o update deveria depender de IdAbastecimento e nao deste campo.
- Ainda assim, o backend precisa esclarecer a relacao entre o erro do indice TB23_CDGWEB e a logica interna de atualizacao.

O backend precisa informar:
- Se TB23_CDGWEB e o mesmo conceito de codAbastecimentoExterno
- Se esse campo precisa ser reenviado obrigatoriamente para update
- Se esse campo e gerado pelo servidor ou deve ser preservado pelo app
